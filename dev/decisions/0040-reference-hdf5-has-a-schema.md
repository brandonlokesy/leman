# 0040 — Reference HDF5 files use a versioned schema

| | |
|---|---|
| **Status** | Accepted |
| **Date** | 2026-09-17 |

## Context

The six reference-data processors each wrote their own HDF5 layout. Signal datasets
were named `spectrum`, `counts`, or `spectra` depending on the processor. The energy
axis lived at the root, at the sweep-group level, or duplicated into every per-spectrum
group. No file carried a format tag, a version, or units on its datasets. The loader
(`loader.py`) compensated with heuristics: a search list
`SPECTRUM_KEYS = ("spectrum", "counts")` that missed `spectra`, and `_find_energy`
that walked up the HDF5 hierarchy. Single-spectrum files (Lin, Louca, Alexeev) put
`energy` and `spectra` as root-level datasets, which the recursive `_read_sweep`
skipped, producing empty `SweepSeries` objects.

The measured-data HDF5 (`hdf5.py`) is versioned (`leman.attocube_sweep` v2.3),
self-describing, and internally consistent. The reference side needed the same
discipline.

## Decision

All reference HDF5 files follow a single schema, `leman.reference` version 1.0, with
three layout variants.

**Root attributes** (all files): `format`, `format_version`, `created`,
`toolkit_version`, `material`, `source`, `title`, `doi`, `dataset_doi`, `about`,
`spectroscopy`. The `spectroscopy` field uses the same vocabulary as the measured
side's `spectra_type`.

**Layout A — single spectrum:** `axes/<energy|wavelength>` (1-D) and
`spectra/intensity` (1-D).

**Layout B — 1-D sweep:** `axes/<energy|wavelength>` (1-D), `sweep/values` (1-D) +
`sweep/default_index` (scalar), `spectra/intensity` (n_pixels, n_sweeps). Pixel axis 0,
sweep axis 1 — matching the measured format.

**Layout C — nested sweep:** `sweep_meta/` with outer-sweep metadata,
`conditions/0/`, `conditions/1/`, etc., each self-contained with its own `axes/`,
`sweep/`, `spectra/`. Each condition can have a different spectral axis and a different
inner-sweep length.

**Signal dataset name** is `intensity` everywhere. It does not clash with `spectra`
(the HDF5 group name on the measured side) or `counts` (the TRPL/Raman dataset name).

**Provenance** is an optional `provenance/` group with free-form attributes and a
`pipeline_summary` string.

**The axis is stored as-is from the source:** if the paper published energy, store
energy; if wavelength, store wavelength. The `units` attribute on the axis dataset
says which. No domain conversion at write time.

**The loader refuses old-format files** with a message to regenerate. The HDF5 files
are gitignored and rebuilt by running `python -m leman.reference.registry`.

**Single-spectrum files** are accessible via both `ref.spectrum` (a convenience
property) and `ref["spectrum"].default()` (wrapped in a trivial `SweepSeries`).

**Writer helpers** on the `Processor` base class (`_write_single_spectrum`,
`_write_1d_sweep`, `_write_nested_sweep`, `_write_provenance`) enforce the schema so
processors stay focused on parsing.

## Rejected

**Make reference data a subset of the measured format.** The measured format carries
instrument metadata (parameter rows, gates, nesting coordinates, ROIs) and a
correction ladder (background, Jacobian, cosmic rays) that reference data does not
have. Forcing reference data into that schema would require stubbing or refusing most
of it, promising more than the data delivers.

**Group-per-spectrum for sweeps.** The old layout stored one HDF5 group per sweep
value, each with its own signal dataset. A flat 2-D array in `spectra/intensity` is
smaller, faster to read (one dataset read instead of N), and matches the measured
format's `(n_pixels, n_sweeps)` convention. For nested sweeps the flat approach does
not work (different conditions have different spectral axes), so the per-condition
group layout is used there.

**Heuristic signal detection.** `SPECTRUM_KEYS` and `_find_energy` tried to be
flexible and ended up covering only some layouts. A fixed schema is stricter but
reliable — every file is readable the same way, and a file that does not match is
refused rather than silently misread.

**Convert wavelength to energy at write time.** Two processors (Vaquero, Dijkstra)
originally converted wavelength to energy. Converting the spectral axis also requires
a Jacobian correction on the intensity for spectral-density quantities, and corrections
are opt-in. Storing the original axis avoids an implicit correction. (Dijkstra's
reflectance contrast is dimensionless, so the Jacobian cancels and energy is valid
there; it was confirmed to keep energy.)

## Consequences

All 8 reference HDF5 files must be regenerated by running
`python -m leman.reference.registry`. Old-format files are refused by the loader.

The loader is now schema-driven: three reader functions, one per layout, reading from
fixed locations. No heuristics, no walking.

A future processor that stores wavelength instead of energy writes
`axes/wavelength` with `units="nm"`. The current loader and `Spectrum` dataclass
assume energy; they will need to evolve when that file arrives.
